## Finding 43: stop hints in Windows shells

Confirmed by executing the former single-quoted project argument through `cmd.exe`: the receiving Node process got the quote characters as part of the path. The initial PowerShell-only fix described in row 32 introduced a real Command Prompt regression and is superseded by this correction.

The shared stop-command formatter now emits arguments readable in both Windows shells when possible: ordinary backslash paths stay unquoted, and safe paths containing spaces use double quotes. Dollar signs, backticks, percent expansion, delayed-expansion exclamation marks, embedded quotes, empty/control arguments and quoted trailing backslashes use a fixed ASCII `node -e` command with base64-encoded argv. Node decodes after shell parsing and invokes the absolute CLI that generated the hint with `execFileSync`, without a shell or a different package install. Ordinary POSIX quoting is unchanged; POSIX control arguments use the encoded fallback too, keeping copied commands on one line. Multi-portal and standalone hints use the same formatter.

Regressions execute exact printed hints through Command Prompt with delayed expansion off/on and PowerShell, using an owned `npx` collector shim to prevent downloads. They preserve spaces, apostrophes, dollar expressions, backticks, literal environment-variable spellings, exclamation marks, carets, ampersands, drive roots, UNC paths, embedded quotes, blank values, tab/newline values and trailing backslashes. Standalone lifecycle tests also execute actual encoded stop hints through both Windows shells and verify that the selected runtime stops while its sibling remains usable.
