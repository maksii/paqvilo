## Measured performance and limits

The sequential Windows synthetic 400-template/600-snippet X-ray probe measured first toggles of 211–219 ms, revisits of 17–20 ms and element identification around 0.03 ms. Navigation to the panel was measured separately; source preparation may overlap navigation. Run `node scripts/benchmark-xray.mjs --samples 3 --strict --json` from the toolkit checkout to recheck the 1,000 ms / 200 ms / 5 ms budgets.

On the same 64-table, 24-field, approximately 10,000-row fixture with identical persisted checkpoint bytes, standalone restart improved from 5,250 to 1,718 ms, first catalogue from 1,800 to 77 ms, and maximum concurrent status latency from 1,779 to 21 ms. Response bytes and row counts matched. Fresh/unchanged/journal-grown portal and standalone matrices retained local edits and generated bootstrap preset bodies only on fresh state. See [runtime loading and responsiveness](../mirage/docs/runtime-performance.md) for reproduction, stage costs, budgets and measurement qualifications.

A further source-volume probe retained 10,498 XML files, 10,240 forms and 20,000 records. Its initial portal catalogue measured 9.6–10.5 seconds and missed the one-second status deadline. After scoped metadata reuse, cooperative construction and indexed reconciliation, portal cold catalogue measured 2.16–2.22 seconds, warm catalogue 0.79–0.85 seconds and status at most 410 ms. Final portal/standalone startups stayed below 11 seconds, retaining every source and record; standalone cold catalogue stayed below 0.9 seconds. Populated first grids took 129–146 ms and record reads 20–27 ms. The source-volume runs use equivalent invented fixtures, not the identical-checkpoint comparison above; their full measurement context and memory limitations are recorded in the linked performance guide.

These measurements qualify the tested synthetic cases. They do not certify arbitrary live-page attribution, a private project's exact startup time, all native Dataverse behavior, or application readiness from a listening port. Cross-origin/opaque frames retain their browser security boundary. Source-only matrix stages remain source diagnostics rather than configured-site acceptance. Capability results are recomputed across requests, so changed staff/security/source inputs cannot reuse an old access verdict.

## Review and validation

The second implementation review independently checked transaction ordering, source confinement, frame context and geometry, budgets, invalidation and lifecycle cleanup. It corrected PCF translation/manifest bytes bypassing the shared budget, controls/assets lost after the shape cap, an inner frame borrowing the host form identity, and frame-relative assets resolving against the host URL. Fingerprint review corrected valid bang-containing source paths. Full validation caught a browser-close/readiness race; a focused regression now covers graceful shutdown during the wait. Large-source profiling prompted additional metadata-epoch, cooperative construction and indexed reconciliation fixes. Full validation, installed-package smoke and branch CI are required before merging these changes back to the 0.9.6 preparation branch.
