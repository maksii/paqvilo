# CI revalidation: physical temporary-directory boundaries

The Windows examples job `122980240231` in CI run `40734723279` failed on PR #30 at head `85ffd9f739fa8ea5b9051d055f349f0eda7b4f81`. This triggered another review and fresh verification; the earlier local pass does not qualify this failure.

## Reproduction and cause

The actual existing `portal packaging discovers component types and uses valid non-Entity flags` test was run in a separate Node test runner with `TEMP`, `TMP` and `TMPDIR` pointing to a newly owned real directory junction. Its temporary creator returned the physical directory, while its cleanup guard compared that directory against the logical `os.tmpdir()` spelling. The packaging operations completed, but cleanup failed at `resolved.startsWith(parent)` and left the `co-security-*` fixture behind.

The unchanged test reproduced **0 passed / 1 failed / 0 skipped**, exit status 1. Its complete output and leftover inventory are recorded in ignored `.paqvilo/audit/ci-red-packaging-before.json`. The reproduction container was removed only after separately verifying its physical containment.

## Fix and additional review

The packaging test registers its owned cleanup immediately after creating the temporary root. Before deletion it calls the shared `assertTemporaryDirectory` guard, which resolves both the target and parent physically and checks separator-aware relative containment. It rejects the parent itself, absolute escapes, parent traversal and prefix siblings. Cleanup uses the returned verified physical path. The site-count, operation-count, component-type and non-Entity flag assertions remain unchanged, as does the `co-security-` prefix.

The new example regression runs that exact packaging test in a real child runner under a junction on Windows or a directory symlink on POSIX. It requires exactly one executed test, zero failures, zero skips and an empty physical temporary parent afterward. It clears only the inherited Node worker marker so this is a separate test runner. Another actual-filesystem regression attempts guarded deletion of the parent, a prefix sibling, a traversal path and an internal link to an external sibling; all must reject while preserving the sibling sentinel and parent. A legitimate owned child remains removable.

A broader search across both example projects and company plugin tests found no second temporary-root ancestry guard comparing a physical created root with a logical parent. Their other temporary cleanup targets come directly from canonical creators; the existing CLR runtime fixture already resolves its created root physically. The shared guard and its Mirage callers were independently cross-reviewed with the Mirage reviewer.
