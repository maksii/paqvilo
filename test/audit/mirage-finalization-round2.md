# Mirage finalization: independent second review

This review checks the first round from a different ownership and failure-order perspective. It covers the model-driven cold grid and application picker, the context-lifecycle regression's sensitivity to its original defect, and the broad temporary-directory conversion's argument and package boundaries. It complements the first-round per-file inventories; it does not substitute focused checks for the required fresh full and hosted validation.

The three new picker cases use real pages and simulator fixtures with controlled protocol responses, not sleeps. Gates release through the fixture owner before cleanup. Existing picker assertions and the original 30-second Copper locator bound remain. The complete picker file passes 15/15 with zero skips; formatting, lint and diff checks pass for the changed runtime and picker files.

The lifecycle mutation fails at `settled: true` versus expected `false` in about 0.5 seconds, rather than failing by timeout. The new focus cases demonstrate causal cold-start and later-route defects. ## SDK preparation and gate review

The independent SDK preparation review found repair and receipt gaps in the initial implementation. A same-version modified wheel, removed transitive dependency or wrong interpreter could leave preparation permanently failing, because pip reused the damaged environment. The owner now verifies a warm environment first and recreates only the canonical owned venv when it is invalid. The focused warm-repair regression fails against the original behavior and passes with repair.

A controlled failed locked restore originally left an old receipt present and accepted by `requireSdkFixtures`: both observations were `true`. Preparation now revokes the previous receipt before mutation; the same independent probe reports both `false`. Interrupted clean sample fetches resume their sparse pinned checkout, while dirty or externally linked source remains rejected.

The preparation owner also isolates Git configuration and environment; the real Windows regression found that Git requires `NUL` rather than Node's extended null-device spelling. The actual WebAPI sample gate still had a raw Git HEAD probe, so this review replaced it with the shared sample-only verifier. The real redirected-Git regression proves the old probe fails and the shared verifier succeeds without touching the unrelated index. Removing the synthetic Python executable and receipt still leaves the sample-only verifier usable; optional WebAPI runs gain no unrelated Python prerequisite.

The resulting SDK preparation suite passes 16/16 with zero skips. The actual required WebAPI sample gate passes 1/1, including construction, WhoAmI, create, retrieve, update, query, delete and batch assertions. The lock contains exact transitive pins and wheel hashes; installation keeps hash enforcement, binary-only packages and the fixed public package index. Linux wheel availability is checked separately by the preparation owner and the hosted Linux SDK lane remains required.
