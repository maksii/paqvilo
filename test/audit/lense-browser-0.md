Cross-cutting root causes found and fixed in this partition:

- A. Windows profile release: with the Windows sandbox (lense `openBrowser` sets `chromiumSandbox` on win32),
  Chromium keeps profile files (chrome_debug.log) open 2-12 s after `close()` resolves (measured 15 rounds:
  2.1-11.9 s sandboxed vs ~8 ms unsandboxed, one 4.6 s outlier). `fs.rm(..., {maxRetries:10, retryDelay:100})`
  (~5.5 s) or no retries failed with EBUSY/EPERM in after hooks (reproduced: model-driven-cleanup-errors 4/6
  tests in one run, multi-portal 2, init-workspace 1). New helper `test-browser/helpers/profile-cleanup.mjs`
  (`PROFILE_RELEASE_RETRIES`, ~32 s bound) used for every directory that held a browser profile.
- B. Released-port probes: "listener closed" checks fetched a released loopback port, which a busy host can
  reassign (observed: `Missing expected rejection` in model-driven-cleanup-errors). New helper
  `test-browser/helpers/agent-endpoint.mjs` (`servesAgentSession`) checks the agent no longer serves its own
  session token; post-exit CLI probes removed (process exit already proves it); demo uses `mirage status`.
- D. Debugging-port reservation race: tests reserved a port with listen(0) (ephemeral range) and released it
  before the browser bound it; under load dev refused it "already in use" after a 15 s Mirage startup (observed
  in init-workspace). New helper `test-browser/helpers/debug-port.mjs` (`freeDebugPort`, free port in 20000-32000,
  below the Windows and Linux ephemeral ranges) used in all 8 files that reserve debugging ports.
- E. Product: first `/__sim/api/state` rehashed the whole Mirage implementation (1414 file reads; ~20 s on a loaded
  host), exceeding the acceptance recipe's 15 s budget (TimeoutError traced to `readState` in mirage/acceptance.mjs).
  The same fix (cached fingerprint at server import) has landed on the lead branch; my duplicate commit was dropped
  on rebase. After the fix the recipe case took 4.7-12 s with no timeout in 8 traced runs (vs 12-29 s and 1/8 timing out).
- C. Child output polling: new helper `test-browser/helpers/child-output.mjs` (`childOutput().waitFor`)
  waits on printed readiness lines event-driven, fails at once on child close, redacts long opaque runs.
