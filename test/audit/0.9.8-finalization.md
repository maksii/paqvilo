## Review coverage

The first round divided Lense, Mirage and infrastructure among parallel reviewers. The second round changed perspectives: the Lense reviewer challenged Mirage startup and lifecycle ordering, the Mirage reviewer challenged CI selection and qualification, and the independent reviewer challenged Windows paths, process identity, benchmark output and SDK preparation. Each concrete finding received an implementation disposition and relevant regression or controlled proof.

- [Lense round 1](lense-finalization-round1.md): 238 test/support JavaScript files, including 222 test files; all 167 temporary allocation sites in that working snapshot are classified. Literal assertion sites increase from 8,034 to 8,063; this is a static preservation count, not a runtime assertion total.
- [Mirage round 1 and infrastructure review](round1-mirage.md): 979 JavaScript files inspected for temporary creation across Mirage, SDK, volume and examples. The [573-site inventory](round1-mirage-temporaries.csv) records every original call and disposition. Originally, 545 roots were uncanonicalized and 28 already canonical; no ordinary raw creation root is left unclassified.
- [Independent Mirage round 2](mirage-finalization-round2.md): held cold-start requests, application selection, stale success/failure ownership, a lifecycle mutation proof, helper/package boundaries, and SDK preparation recovery.
- [Hosted-failure review](ci-round3-temporary-boundaries.md) and [Mirage CI revalidation](ci-round3-mirage.md): physical TEMP/consumer boundaries, physical-volume capability selection, panel transport draining, controlled child-navigation ordering and retained synthetic failure evidence.
- [PCF transport revalidation](ci-round4-pcf.md), [Xray ordering revalidation](ci-round4-xray.md) and [diagnostic security revalidation](ci-round4-security.md): the next hosted failures, independently challenged fixes, controlled failure proofs and preserved assertions.

The shared canonical creators now live in `mirage/testing/owned-fixture.mjs`. The independent pre-consolidation check compared all 573 original Mirage/example argument lists and resolved all 336 new helper imports without a mismatch. Later fixture consolidation moves repeated creation into shared builders while preserving the complete prefixes, assertions and intentional alias/security descendants. The original inventories remain snapshots, rather than claiming unchanged final literal call counts after extraction.
