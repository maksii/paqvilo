# Audit record: cache-correctness

Branch `worktree-agent-a4afbfb63fcfa7e72` (from `claude/test-performance-audit-9ec376` f42e038a). Scope: every
stat-, mtime-, size- or identity-keyed cache and change detector in `lense/` and `mirage/` (plus the one in
`scripts/ci.mjs` found by the grep), checked for the "racy stamp" bug fixed first in `mirage/lib/evidence.mjs`: file
times advance in ticks, so a same-size rewrite in the tick of a cached read keeps size, mtime, ctime and inode.

Shared rule (new, `lense/file-cache.mjs`): `RACY_WINDOW_MS = 2000`, `racyStat(stat)` (mtime or ctime within the
window of now) and `recordedStamp(stat, value)` (the stamp to keep beside content read after `stat`: `value`, or a
never-repeated value while racy). As in Git's racy-entry rule the check is made when the entry is recorded, so a
settled (unchanged for > 2 s) tree still compares stats only; only files written in the last 2 s are read again.

Regressions freeze the times every stat call reports (`mirage/test/support/file-times.mjs freezeFileTimes`), which
reproduces the same-tick condition on any file system: each fails on the old code every run (Windows 3/3, Linux 3/3),
passes with the fix, and a `settled` twin proves unchanged files are still reused without a read.
