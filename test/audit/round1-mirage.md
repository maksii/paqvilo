- The Linux SDK workflow now invokes explicit npm lifecycle scripts, ensuring the executing npm CLI path is supplied by npm itself. This avoids depending on Windows' npm installation layout.
- Validation receipts now identify the selected CI browser channel, its actual executable and Chromium's separate headless-shell executable. Another channel or changed binary invalidates prior evidence.
- Verification now consumes earlier receipts before argument/source/browser qualification, so an early failure also revokes old evidence. The early-failure regression fails before and passes after.
- Benchmark dependency qualification rejects linked contents that could mutate outside the fingerprinted package. The real-link regression fails before and passes after. The actual prepared toolkit qualifies with 191 packages and 9,954 ordinary files. Existing output traversal, tracked-file, linked-parent and exclusive-write checks pass.
- Shared browser fixture teardown drains every independent browser/server/app closer, including when one fails. Admin fixture ownership starts before context creation. Two controlled regressions cover context creation failure and a context-close failure; a failed close retains potentially active fixture files.
- The Python SDK child receives the test cancellation signal. A controlled held-child regression cancels that signal, verifies the child exits through cancellation and verifies the gate cannot qualify success.

The ownership and infrastructure review batch runs fresh with **77 passed, zero failed/cancelled/skipped**, including receipt/workflow/contribution/PR-readiness/qualification coverage and the affected admin/lifecycle browser files (21.59 seconds). ## Final TLS prerequisite audit

A fresh Windows run before the tool-resolution fix reports 8 passed and 2 skipped: both OpenSSL assertions were bypassed because OpenSSL was absent from PATH, although Git for Windows includes a working copy. The TLS fixture now prefers PATH and falls back to Git's own installation, discovered through `git --exec-path`; it invokes that executable directly and leaves PATH unchanged. The actual TLS file runs fresh in required mode with **10 passed, zero failed/skipped** (1.59 seconds), preserving all certificate, name-constraint, trust and regeneration assertions. Three injected resolver tests cover PATH preference, the real Windows layout with spaces, launcher fallback, absent tools, POSIX behavior and required-mode failure. The combined targeted run passes 13/13. Formatting and ESLint pass. Evidence is retained under `.paqvilo/audit/round1-mirage/tls-tools-{before,after,required}.tap`.
