OPEN SOURCE · LOCAL-FIRST · POWER PLATFORM

Power Pages and Dataverse development, on your machine.

Paqvilo lets you run your exported Power Pages site locally, together with a Dataverse Web API, plug-ins, cloud flows and model-driven apps, and preview local edits on a live portal without uploading them. Fewer deployments between an idea and a working page.

Run the local demo →Open the developer guide →

Free and open source (AGPL-3.0-only) · Node.js 26 · Edge or Chrome · Windows and Linux · no Power Pages account needed for the demo

ONE TOOLKIT. TWO WAYS TO BUILD.
Your exported sources. Your feedback loop.

WHAT RUNS LOCALLY

Stop deploying to see a change.

Power Platform development usually means edit, upload, wait, clear the cache and refresh, in a shared environment that has to be online and available. Paqvilo reads the sources you already export with the Power Platform CLI and runs a local working model of them, so most of that loop happens on localhost.

  • Power Pages sites

    Render an exported site on localhost: Liquid templates and snippets, basic and multistep forms, lists, languages, web roles and table permissions, with local sign-in as test personas.

    Power Pages capabilities →

  • Dataverse Web API

    A local Dataverse organization for API testing: OData CRUD, $metadata, $batch, FetchXML, security roles and OAuth app registrations, checked against Microsoft's ServiceClient and MSAL.

    Local Dataverse API →

  • Dataverse plug-ins

    Run the plug-in steps of your Solution in a local pipeline as mocks or JavaScript models, or, on Windows with the Dataverse SDK assemblies installed, load your original .NET Framework assembly and attach the VS Code debugger, without the Plug-in Profiler.

    Local plug-in debugging →

  • Model-driven apps

    Open exported apps locally with sitemaps, views, grids and main forms. With trusted extensions enabled, form scripts and ribbon commands run against a bounded Xrm and formContext client API.

    Model-driven apps locally →

  • PCF code components

    Host your built controls on local portal pages, portal form fields and (with trusted extensions enabled) model-driven forms and subgrids, bound to local records instead of mock inputs.

    PCF local hosting →

  • Power Automate cloud flows

    Execute exported flows in a local interpreter: Power Pages, HTTP, recurrence and Dataverse row triggers, control actions, variables and expressions. Dataverse actions run on local data; other connectors use local providers or mocks.

    Flows and server logic →

  • Canvas and code apps

    Play exported canvas apps in a local player that evaluates their Power Fx on local data, and run a Power Apps code app's dev server through a local bridge with a Vite plug-in.

    Canvas and code apps →

  • Tests and AI coding agents

    Repeatable Node tests against the local runtime, --json output from the inspection, audit and status commands and a bounded browser API give CI and coding agents a way to check a change without a cloud environment.

    Testing and automation →

HOW IT WORKS

Two tools, one set of exported sources.

Both read the portal and Solution folders you already keep in Git. Neither downloads, uploads or deploys: that stays with the Power Platform CLI.

01 / RUN IT LOCALLY

Mirage

A local simulator. It serves your site and apps on loopback with local Liquid rendering, simulated Dataverse data and the permissions from your export. It works on local state unless you explicitly opt in to live reads or writes.

  • Sign in as different personas and compare what each one sees
  • Load repeatable data sets, mock operations and trace every request
  • Manage the running simulation in the local /_sim/ workspace
Develop a site locally →

A model of selected platform contracts. A passing local scenario is not platform parity.

02 / PREVIEW ON THE LIVE PORTAL

Lense

A live preview. It opens your deployed portal in a dedicated browser and serves your local JavaScript, CSS, images and literal markup edits in place of the deployed ones.

  • Saved stylesheets usually swap in place; other changes reload the affected tabs
  • Select an element to see the source that owns it, or the candidates when the export cannot tell
  • See which edits applied and which still need a deployment
Preview on a live portal →

Liquid and Dataverse run online. Browser actions can change live data.

TRY IT NOW

A working portal from three commands.

The demo copies an invented sample portal into your folder and opens it in a development browser: native forms and lists, a Power Pages Web API workspace, PCF field components, plug-in steps and a cloud flow. Edit a portal source and the page follows.

HONEST SCOPE

A development tool, not a platform replacement.

  • A simulation, not an emulator. Mirage models the parts of Power Pages and Dataverse it documents, and tells you when a page uses something it leaves out. Check what matters in a real environment before you release.
  • No cloud connectors. Flows, canvas apps and code apps never call a real cloud connector locally. Dataverse actions use local data; for the rest you supply a provider or a mock.
  • Some features are opt-in. Beside a portal you switch the Dataverse API endpoint on in configuration, model-driven scripts and PCF need trusted extensions, original .NET plug-in assemblies load on Windows only, and portal pages do not host React (virtual) PCF controls.
  • Deployment and licensing are unchanged. Lense and Mirage do not deploy or host production sites, and nothing here replaces Microsoft licences. Export and deploy with the Power Platform CLI as before; the separate paqvilo dataverse commands provision project schema in an environment you administer.
