# Company Operations regression project

This separate project owns the business model, synthetic data, portal security/harness and plugin laboratory from the [three implementation specifications](../../docs/design/company-operations-demo.md). Reusable API/CLI provisioning stays in [`paqvilo/dataverse`](../../docs/dataverse-provisioning.md). Environment identities, credentials, exports, deployments, actual tester bindings and observations stay under ignored `.paqvilo/`.

The model contains 27 tables (24 custom plus Account/Contact/Currency), 26 choices, 71 relationships (63 lookups and eight native N:N relationships), 27 alternate keys and 192 scalar columns. Twelve independent role principals anchor scoped access. The required permission path has eleven tables and ten Parent edges. Permanent, fixed-term and external engagements can overlap across companies.

`prepare-schema.mjs` derives the [metadata manifest](dataverse/manifest.json) from the reviewed specifications and reference projection extension. Metadata is created through the Dataverse API and exported from the server. The five metadata/code solutions are Core, Forms, TestSupport, PluginEvidence and BehaviorPlugins. A separate `PaqviloCompanyOperationsPortal` solution carries one explicitly selected website after those prerequisites.

Initialise a fresh environment with `paqvilo dataverse apply` using the manifest, then publish, wait for active keys and seed the merged catalogue before activating/importing Behavior plugin steps. OperationIntentGuard server-stamps new operation markers, so the authored incomplete seed operation must be created before that guard becomes active; never relax the guard to reproduce placeholder markers. The scoped native ZIPs require existing tables; they preserve dependency direction and do not claim to create a new environment by themselves. Project forms/views are reconciled separately after table-root scoping. Microsoft requires full-table packaging for first-time native table imports; this project's initial-install route is the API bootstrap.

The [base catalogue](data/catalogue.json) has 820 records, 305 association links and 24 personas. `prepare-stress-data.mjs` adds a twelve-role persona with three simultaneous engagement kinds and role activation variants. The [merged catalogue](data/stress-catalogue.json) has **842 fixture/reference records, 434 links, 25 personas, 29 scenarios and 43 backend retrieval checks** and is the default environment baseline. Base-only exact association comparison is insufficient after installing the extension. Thirty-six records are isolated A/B mutation canaries; five complete eleven-node paths cover independent roots and custody/history variants. Observations are created only by execution.

```sh
npm install
npm run schema:prepare
npm run data:prepare
npm run stress:prepare
npm test
npm run test:browser
npm run data:plan
npm run data:apply -- --connection /absolute/path/to/private.connection.json
npm run data:compare -- --connection /absolute/path/to/private.connection.json --out .paqvilo/dataverse/compare.json
npm run data:query -- --connection /absolute/path/to/private.connection.json --out .paqvilo/dataverse/queries.json
```

Loading is additive: active keys, resolved navigation properties, conditional creation, explicit deferred lookup cycles and exact N:N comparison. Drift stops loading. `data/reconcile-seed-headers.mjs` narrowly updates schema hashes on untouched incomplete seed placeholders; it refuses executed runs or observed results/events and uses ETags. Company root lookups remain null, descendants identify their Company, and Vendors have no organisational root. Dataverse rejects a Company-to-itself root association.

The form compiler creates 39 named main forms and 71 public views, plus existing Lookup/Quick Find adjustments on all 24 custom tables. Portable surfaces omit private fields, grants, ancestry and custody lookups; administration forms use real related subgrids. Standard Account/Contact forms and system views are preserved. Run `forms:audit` or `forms:apply` with `--connection FILE`. Generated IDs, before/after receipts and compiled metadata stay private. This environment rejects Quick Find FetchXML updates through the record API, including unchanged XML. `forms:import-quickfind` edits only those view nodes in a native exported solution, imports asynchronously, publishes and verifies readback. Interrupted imports resume with `--resume JOURNAL`. Microsoft documents [views and unmanaged XML imports](https://learn.microsoft.com/en-us/power-apps/developer/model-driven-apps/customize-entity-views).

The [security toolkit](portal-security/README.md) provisions thirteen web roles (twelve business plus the recorder), role-specific Contact roots, deep Parent permissions and scoped Currency/Vendor reference leaves. Website configuration is explicitly selected and audited for Global contamination. Native enhanced-model associations are serialized in component content; empty virtual N:N reads are insufficient. Role variants preserve unrelated assignments and the recorder.

The [portal harness](portal-harness/README.md) provides one visible page, 37 paired Liquid/API FetchXML observations, native OData and query-budget variants, guarded canary/probe mutations and stored history/diffs. Visibility oracles derive from the intended permission graph and remain separate from observed portal behavior. Actual signed-in Contacts use private bindings. Safe scalar name changes and disposable stock-equipment CRUD work where permissions and guards qualify; structural scope/lifecycle mutations remain protected until projection reconciliation is implemented.

The plugin laboratory records incoming queries and typed context/image/chain/configuration evidence. Operations use server-stamped UTC/GUID markers and immutable ownership/evidence guards. Live SDK qualification, real portal qualification and offline tests have separate receipts. Transactional evidence can roll back with a failing request and is labelled accordingly. Durable Azure capture, managed-identity federation, Key Vault and the secret verification flow require external resources and qualification; their source contracts do not claim deployment. `RetrieveEnvironmentVariableSecretValue` belongs to the supported flow path.

Backend comparison/retrievals use the application identity and prove fixture integrity. Permission visibility, collisions, API behavior and query expansion require the intended signed-in website. Retain errors, incomplete runs, configuration changes and cleanup residuals; parity alone does not prove either lane is correct.

Signed-in qualification uses the project's intended Edge connector, with private tester bindings. The baseline paired suite retains authorization differences and query-limit failures rather than calling them empty successes. The isolated complete-subtree variant qualified Checklist/Inspection/Finding at 9/17/17 records in both lanes, matching independent IDs; Liquid and backend XML contained 9/10/11 joins. The baseline's overlapping IT paths expanded those queries past the platform limit. A separate unsafe parent-only fault exposed cross-organisation records and was restored; deployment now rejects active children beneath inactive parents. Joined Liquid finance projections also exposed seven unexpected synthetic GUIDs while the API denied access. These are recorded target-site findings, not proof of universal platform behavior, and require independent scope assertions in future regressions.

All six actual tester role masks (0/1/2/4/8/12) were observed and exercised with four bounded query-budget cases each. Twelve simultaneous business roles triggered the API join limit even with zero authored joins. Afterwards the original role assignments and IT baseline were restored, all eleven temporary grants were revoked/cleared, and native security readback found no configuration drift or active orphan permissions. This qualifies one real tester's controlled combinations; the remaining synthetic personas have independent model expectations rather than an asserted sign-in pass.

Client artifacts now use reversible UTF-8 base64 transport, original full byte length/hash and per-part checksums. This prevents the observed portal rewrite of embedded API context URLs from corrupting stored raw bodies. Older integrity failures remain unchanged. The runner enforces a configurable 20 MiB client transport budget and rejects overlapping runs; combined client/server quota and durable rollback capture require the external collector.
