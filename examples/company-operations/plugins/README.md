# Company Operations plugin lab

Project implementation of [the plugin specification](../../../docs/design/dataverse-plugin-observation.md), using the [company model](../../../docs/design/company-operations-demo.md) and [single-page harness](../../../docs/design/power-pages-permission-test-harness.md). Source belongs to this demo project. SDK/application tests do not establish Power Pages Contact authorization.

Two strong-name signed .NET Framework 4.6.2 assemblies use pinned `Microsoft.CrmSdk.CoreAssemblies` 9.0.2.60. NuGet lockfiles are committed. `LabPublicSigning.snk` is an intentionally public synthetic signing fixture copied from the established example. It is not a production certificate or managed-identity federation credential. Builds, environment-specific registrations, exported solutions and observed evidence stay ignored.

Bootstrap the project schema through its Dataverse manifest/API tooling before installing plugins. Exported solutions use explicit table subcomponents and are update packages for that provisioned schema; they are not standalone installers for new custom tables. Behavior owns six added attributes, three relationships and five supplemental forms, while its table definitions and primary names come from Core, Support and Evidence prerequisites.

From the toolkit checkout:

```powershell
dotnet build examples/company-operations/plugins/QueryObservation/QueryObservation.csproj -c Release -p:RestoreLockedMode=true
dotnet build examples/company-operations/plugins/PipelineTests/PipelineTests.csproj -c Release -p:RestoreLockedMode=true
node examples/company-operations/plugins/prepare-registration.mjs
node examples/company-operations/plugins/deploy.mjs --connection .paqvilo/dataverse/provisioning.connection.json
node examples/company-operations/plugins/deploy.mjs --apply --connection .paqvilo/dataverse/provisioning.connection.json
node examples/company-operations/plugins/provision-owner-team.mjs
node examples/company-operations/plugins/verify-live.mjs
```

`deploy` without `--apply` is read-only. Utilities accept `--connection` and verify the saved expected organisation before accessing it. Application is resumable by stable component IDs, with fresh reads before creation. SDK message filters are discovered in the connected environment; `iscustomprocessingstepallowed` must be true. Live qualification found Currency RetrieveMultiple and ChainNode Upsert filtered steps unsupported. Upsert succeeds through its observed Create/Update pipelines; it is not presented as an observed Upsert pipeline. Associate/Disassociate use global message registrations with explicit relationship/entity checks; RetrieveMultiple registrations are always table-specific. The deliberate query mutator is disabled by default and remains an unqualified SDK-only calibration.

The authored registry currently contains 231 step intentions; the installed configuration has 223 eligible steps and 36 exact-column images. Assembly/type registrations, Custom API request/response parameters, five environment-variable definitions and a narrow owner-team role are included. Create postimages use the `Id` message property, while Update/Delete use `Target`. Images are never registered on an unsupported message/stage. Exported assembly/type and step/image components follow their solution roots; they are not independently invented components.

`upload-assemblies.mjs` updates only existing assembly content after a local build. `update-guard-config.mjs` provisions explicit registered chain-step provenance on the three ChainNode guards. Full fresh installation obtains these IDs directly from `deploy.mjs`. Secrets are generated in memory for the two synthetic secure-config profiles and sent only to secure step configuration. The [secure provisioning contract](secure-provisioning.json) contains symbolic references and safe version labels, no secret values. Secure configuration is not carried by solution exports.

The SDK runner creates fresh run/probe/operation identities, keeps every attempt, stores client outcomes on its operation, and writes private detailed reports under `../.paqvilo/plugins/`. It does not mutate business canaries. Live positive profiles cover ABC, leaf CRUD/read queries, self N:N association/disassociation, alternate-key create/update Upsert, node ownership Assign, state Update/SetState comparison, typed Custom API echo, async mode, shared context/tag and ordinary environment configuration. P02 captures QueryExpression and QueryByAttribute; a separate marked Account read captures exact FetchExpression XML at four stages. Pre/post images, sparse Target, typed SDK values, backend identities and safe secure A/B version labels remain separate evidence. Root and bounded parent snapshots expose optional SDK2 portal flag/Contact, SDK4 image collections with explicit bounds/truncation, SDK5 user-agent presence with header value redacted, SDK6 environment/tenant and SDK7 application-user fields. Interface availability and successful getter observations are separate; false, empty GUID and unavailable remain distinct. Every payload identifies its capturing assembly name/version/MVID, mapped to local build SHA256 by the private installation audit. No runtime filesystem or binary hashing is used.

The depth adapter creates one bounded SDK child per hop. Budgets 1, 3, 7, 8, 9 and 10 are explicit scenarios, not a normal read side effect. This environment observed committed maximum Depth values 4, 6, 10 and 11 at the first four budgets; budgets 9 and 10 returned platform fault `0x80044182` and the runner verified probe/child rollback. No platform limit was changed. Platform execution Depth is not the table-permission relationship depth. Failed-hop evidence is not durable in the current transport mode.

The first request attaches one immutable `tag`. Later chain requests inherit it; writing a different descendant tag caused a real platform duplicate-key fault during qualification. Namespaced SharedVariables and immutable operation lookups carry individual lineage. Specialized SDK operations can arrive as different messages or under an internal system UserId; snapshots preserve the actual UserId and InitiatingUserId. Internal node Delete/ownership Update exceptions require a configured trusted ancestor and matching immutable operation, plus exact configured step-ID provenance. Dataverse can replace custom caller contexts with ObjectModel Implementation contexts and drop caller variables. ChainB therefore seals its actual configured step ID into server-owned node configstatus before B -> C; disposable leaves inherit it. Similar step names never authorize a mutation. When internal contexts discard the trusted parent UserId, the exception additionally requires the exact sealed registered step, the sole configured SDK app as current InitiatingUserId and a same-operation ObjectModel ancestor. Initiation alone, wrong operation, unregistered proof and direct portal initiation remain denied. Actual portal P02/P05 qualification is tracked separately from SDK qualification. Direct portal node mutations remain denied.

Operation intent stamps actor from its Run relationship, GUID and UTC markers on the server. Portal Create accepts only Liquid/WebAPI lanes and a default Pending capture state; the backend can insert that default even when the browser omits it. Nondefault capture states, nonnull actor/markers and backend summaries are rejected. Update permits only authored query/hashes/client summary/Liquid XML/client finish time; protected null updates are rejected too. Platform-injected primary ID, modification metadata and timezone stamps are distinguished from application fields. Probe triggers validate matching run/actor, Update intent, probe table, selected case/profile, lane, fresh nonce and bounded budget. Raw markers provide correlation, never actor authentication. Portal-lane query capture uses the platform portal flag and nonempty PortalsContactId when available: the Contact must match the immutable intent actor, and empty/mismatch/getter failures withhold capture. A matching platform Contact permits legitimate authored filters on other Contact records. When the interface is unavailable or its portal flag is false, capture conservatively requires at least one permission-shaped Contact/principal EQ predicate, with every such GUID agreeing with the actor. That fallback is labelled observed query binding, not identity attestation, and can produce false negatives for unusual rewrites or business Contact predicates. Rejections leave query/results unchanged and never write foreign evidence. SDK-lane capture additionally requires a configured trusted caller and immutable SDK actor provenance. Controlled SDK child capture requires matching operation, trusted caller/ancestor and exact registered chain-step lineage. Shared portal backend identities are not blanket trusted SDK callers.

Server events are write-restricted to configured recorder identities. All seven Access scope-projection N:N relationships are protected from untrusted association/disassociation. Run/owner moves and cross-run result/probe bindings are rejected. Full business scope/lifecycle projection reconciliation is not installed. The qualified mutable surface is intentionally small: names, Contact first/last names, membership work contact details, equipment manufacturer/model/serial/condition, selected descriptions and employment contract reference. Structural selectors, dates, financial fields, keys, lifecycle states and relationships remain maintenance-only. Disposable equipment Create requires a nonempty name, kind and condition, a `CO-CANARY-` tag, Stock state, a room whose site owns the exact supplied Account, and no forged/current assignment. Create and Delete require an existing `pqvd_canaryrunid` with a nonempty immutable Contact actor; portal binding uses native own-Run Append To, and cleanup uses its Delete-only child permission. The FK cannot be changed or cleared. Delete additionally checks Stock state and no current assignment; ordinary equipment Delete is not granted. Dataverse Restrict relationships still enforce dependent-record deletion. Power Pages must independently grant scoped Read/Append/Append To on referenced records.

Current capture mode is **TransactionalLab**. Complete payloads are saved as Unicode-safe immutable event parts, with full SHA256, and operation headers remain Partial with `DataversePlugin.TransactionalLab.RollbackVulnerable` provenance. A recording SDK write fault aborts the transaction; it is never caught and continued as a successful business action. Neither rollback durability nor capture Complete is claimed. Trace-only mode records safe IDs/hashes, not full queries.

[Collector/worker source](collector/deployment.json) prepares authenticated Entra v2 JWT ingress and durable private Blob receipts before HTTP202, followed by independent idempotent Dataverse evidence writes. JWT role arrays, tenant/audience/issuer, GUID writer identity, envelope identity and payload SHA256 are checked. The plugin validates an exact bounded matching durable receipt and shares its eight-second transport budget through operation lineage. SDK managed-identity token acquisition is synchronous and cannot be locally cancelled; overruns are measured and no subsequent HTTP request proceeds. Hosting, federation version2/certificate binding, storage/RBAC, independent worker scheduling and rollback qualification are installation dependencies and are not deployed here. Unmatched receipts are retained privately; the worker never guesses a Contact or fabricates a bound operation. Total run quota/retention and out-of-order completion reconciliation need hosting qualification before full durable mode.

P08 rollback with durable acknowledgments and P13/P14 Azure/flow secret profiles are blocked until their dependencies exist. [The flow contract](collector/flow-secret-contract.json) identifies the flow-only `RetrieveEnvironmentVariableSecretValue` action and exact `EnvironmentVariableName` parameter. No direct plugin bypass is attempted. The contract is not a deployed Power Automate flow; FlowCallback, connection references, synthetic Key Vault binding and identity qualification remain required. Optional bulk and Merge profiles are also unqualified.

The SDK fixture checks and project Node tests cover immutable intent, redaction, typed queries, inert observers, marker ambiguity, XML entity protection, safe scalar updates, protected scope associations, durable receipt validation, worker envelope integrity and Unicode chunk reassembly. These are local models; live evidence is separately labelled in private qualification reports.

Anonymous observer preparation is a separate opt-in contract, disabled by default and awaiting deployment qualification. Set `allowAnonymousObservation: true` with an explicit bounded `anonymousObservationTables` whitelist in both intent-guard and query-observer configuration. Only the configured SDK recording writer may create an immutable intent with provenance `AnonymousPortal.ConfiguredSDKIntent`, a nonempty controller Run and an allowed RetrieveMultiple table/lane. The observer requires an actual root portal call, available Context2, `IsPortalsClientCall: true`, and an empty `PortalsContactId`. It records `RuntimeAnonymousPortal.ConfiguredSDKIntent`; the controller Contact is never treated as the anonymous request identity. Signed-in, nested SDK, untrusted creator and getter-failure requests cannot use this provenance. A dedicated anonymous dispatcher and fresh registration/assembly receipts are required before native qualification; existing signed-in campaign receipts remain bound to their original DLL bytes.

Owned evidence retention also has a source-only opt-in contract awaiting native deployment qualification. `allowOwnedEvidenceDeletion: true` requires exactly one trusted `writerId`. The exception permits only a root Delete of `pqvd_pluginevent` with no parent, native portal flag false, and that SDK writer as initiator. Its immutable shared-variable tag is `CO-OWNED-EVIDENCE-DELETE:<maintenance-intent-GUID>`. The SDK-created maintenance intent must be at most 30 minutes old, belong to the archived Run, use SDK lane/expected Delete/root recording table, bind `pqvd_caseid=ARCHIVE-OWNED-EVENT:<event-GUID>`, `pqvd_pairkey=<original-operation-GUID>` and `pqvd_variant=SHA256:<full-event-hash>`. Native creators of the maintenance intent, evidence and Run must be that writer. Archive and verify the complete event first, then seal the exact retained intent and per-row archive journal before deletion. Evidence from other Runs, changed hashes, another target, a portal call or nested SDK call fails. Rejection tracing exposes safe identity/stage/origin metadata for diagnosis. Local context fixtures verify this guard; named SDK request `tag` transport in Mirage and native owned-cleanup execution remain separate qualifications. The [official tag contract](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/optional-parameters#add-a-shared-variable-to-the-plugin-execution-context) specifies an SDK request parameter or Web API URL query parameter, rather than a guessed header.

`mirage-runtime.mjs` binds the original exported assemblies and exact registered step IDs to Mirage. Supply a fresh native registration snapshot, installed/exported assembly hashes, an external pinned SDK, an owned cache directory and explicit backend grant profiles for both the portal caller and recording writer. It rejects a hash mismatch or unresolved selected registration; it does not download assemblies or enable a runtime from export discovery alone. Native secure values are never read or copied. Secure constructor checks can use installation-safe synthetic fixtures, labelled separately from native secret values.

`applyNativeDataSnapshot` replaces local tables and projection edges atomically from frozen native reads. It retains actual platform defaults and consumes the snapshot's row-version metadata without adding it to selected SDK Attributes. A separately supplied version map must carry its own frozen-read qualification. `contextFromNativeCapture` keeps safe observed context metadata and portal input flags, while user-agent values remain withheld. `setReadContext` changes only that frozen replay profile and must be called between completed serialized reads; create separate bindings for concurrent instances. `compareRecordedContexts` compares stable fields, including input, output, images, interfaces and shared variables. Generated clocks, request IDs and spans still require matching presence and type; only their valid generated values are excluded. A full snapshot is never labelled byte-equal.

`replayNativeReadBatch` executes each authored physical FetchXML request independently and compares original DLL artifacts, raw incoming queries, SDK collections and stable contexts. It restores local intent/evidence rows between requests and after failure. Pass `sourceWitness: {before, after, registrationSha256}` from actual native reads around the capture: permission, membership, data and row-version hashes must match each other and the snapshot installed by `applyNativeDataSnapshot`; the canonical registration hash must match the binding receipt. Artifact equality alone cannot set `allQualified`. Missing authored queries and prebackend HTTP denials remain explicitly unqualified until the relevant HTTP adapter is exercised. `persistentHost: true` reuses the verified CLR process while constructing a fresh plugin instance for every invocation; call `binding.close()` in `finally` to release these owned processes.

Native recording equivalence requires submitting authored XML through the imported permission graph, executing these original assemblies and comparing the actual generated captures with the corresponding physical native page. Supplying an already expanded native query verifies CLR execution separately and does not prove the permission compiler.
