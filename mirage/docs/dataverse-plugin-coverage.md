# Dataverse plug-in coverage audit

This inventory covers portal, standalone organization HTTP, SOAP, local SDK,
provider and project entry points. It distinguishes implemented behavior from
missing native functionality. Passing the listed regressions does not establish
universal equivalence with an online organization.

| Area           | Implemented contract                                                                                                                                                                              | Remaining gap or qualification boundary                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registration   | Solution assembly/type/step/image discovery, dependencies, mutable registration rows, enabled/disabled state, explicit execution choices and constructor configuration                            | Exports omit secure configuration and unexported system handlers. Original execution requires separately trusted original bytes, dependencies and secure configuration; inventory alone cannot establish the deployed assembly or complete native registration set.                                                                                                                                                                                  |
| Messages       | CRUD, Retrieve/RetrieveMultiple, Associate/Disassociate, standard CreateMultiple/UpdateMultiple and source-defined custom API pipelines; table/message availability from metadata                 | Assign, SetState, Upsert, Merge, other bulk and classic-action handlers do not implement their own plug-in pipelines. Explicitly configured executable steps for missing pipelines stop admitted requests before delegated effects. A CRUD-based operation simulation is not named-message parity. Unsupported SDK messages fail explicitly.                                                                                                         |
| Steps          | Source table bindings, explicit unfiltered read/association registrations, attribute-presence filtering, step identity and evidence-backed execution identities                                   | Arbitrary impersonation, privileges absent from the source security profile, native sandbox restrictions and unsupported deployment combinations are not inferred. The trusted local CLR process is not a Dataverse security sandbox.                                                                                                                                                                                                                |
| Pipeline       | PreValidation 10, PreOperation 20 and PostOperation 40 for supported messages; mandatory custom API MainOperation 30                                                                              | Stage 30 is not a general extensibility stage. Unexported platform handlers and unsupported message stages need a separately qualified implementation.                                                                                                                                                                                                                                                                                               |
| Execution      | Ascending ranks in each stage, qualified scalar/multiple grouping, synchronous requests and committed asynchronous jobs                                                                           | Equal-rank local ordering is deterministic for repeatability, but does not predict native equal-rank ordering. Cloud scheduling, service protection, worker recovery and delivery timing are not reproduced.                                                                                                                                                                                                                                         |
| Images         | Registered aliases and selected columns, pre/post snapshots, stage/message availability and Context4 bulk image collections                                                                       | A read result's implicit primary-key projection must not be applied to an image. Images for unsupported named pipelines are unavailable. Source metadata and an explicit image adapter are required; exported definitions alone do not prove online image contents.                                                                                                                                                                                  |
| Context        | Typed InputParameters/OutputParameters, Target forms, source/local identities, Depth, ParentContext, SharedVariables, system parameters and scoped response handoff                               | Locally generated IDs/timestamps differ from native values. Additional interface properties and transport envelope observations require evidence. Unsupported values and ambiguous metadata fail explicitly.                                                                                                                                                                                                                                         |
| Data semantics | Partial updates, absent versus null values, presence-based filters, pre-persistence Target mutation, Create identity channels/default timing and effective permission revalidation                | Native business/system rules absent from the source remain absent. Local numeric/query behavior requires source types, precision and supported query shapes.                                                                                                                                                                                                                                                                                         |
| Runtime/SDK    | Original IPlugin.Execute, IServiceProvider, service factory, tracing, scoped IOrganizationService calls and the documented typed-value codecs                                                     | The adapter is a bounded SDK subset. Authored SDK optimistic-concurrency behavior, non-null OrganizationRequest.RequestId, configured ColumnSet.AttributeExpressions/ForceSeek/SubQuery/order Alias, Entity.RelatedEntities graph writes, arbitrary SDK request classes, unsupported metadata/value contracts, external services and arbitrary caller identities need explicit adapters; original CLR execution is Windows/.NET Framework dependent. |
| Behaviour      | Nested operations, depth/chain limits, independent top-level PreValidation SDK writes, joined transactional stages, rollback, source faults, asynchronous failure and explicit four-attempt Retry | Native configurable recursion/service limits, cloud backoff and crash recovery are not inferred. Completed asynchronous SDK requests remain independent; a failed job cannot undo the committed caller.                                                                                                                                                                                                                                              |
| Validation     | Invented regression fixtures, original compiled CLR callers, transport/provider tests, failure controls and separate project-native recording/replay                                              | Test counts and successful HTTP responses do not qualify untested behavior. Native proof must identify executed bytes, context/results, failure behavior and owned cleanup. Platform-wide exact parity remains unproven.                                                                                                                                                                                                                             |

The current regression families include:

- Read/query conversion and response identity: `read-pipeline-parity`,
  `plugin-sdk-query`, `plugin-read-post-inputs`, `dataverse-soap`, `dataverse-soap-query-facets` and
  `read-lambda-truth`.
- Mutation and authorization: `plugin-create-identity`, `plugin-sdk-create-id`,
  `update-main-rebase`, `profile-effective-write` and `plugin-target-removal`.
- Registration, named-message admission and execution:
  `plugin-registration-policy`, `plugin-message-admission`, `plugin-bulk-http`,
  `customapi-plugin-pipeline`, `plugin-association` and `plugin-async`.
- Context, values and retained capabilities: `plugin-message-values`,
  `plugin-value-codec`, `plugin-sdk-tag`, `plugin-execution-lifetime`,
  `trusted-handler-invocation`, `store-operation-isolation` and `plugin-clr-lease`.
- External boundaries: `webhook-sdk-values`, `webhook-message-values`,
  `business-logic-ownership` and the local project extension tests.

Private native evidence belongs in the project's ignored state, with reusable
code and invented regressions in this repository. The permission-query reducer
is a project example, not a core business rule or a reason to alter organization
query limits. See [execution details](dataverse-plugins.md),
[project extension guidance](../../docs/project-extensions.md), Microsoft's
[event framework](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/event-framework),
[registration and images](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/register-plug-in)
and [exception handling](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/handle-exceptions).
