# Platform stack coverage

A map of how Mirage covers the Dataverse and Power Platform stack: which module owns each area, the level it reports,
and the guide that holds its contract. Levels (`inventory`, `contract`, `behaviour`, `native-qualified`) are defined in
[capabilities and preflight](capabilities-and-preflight.md#fidelity-levels); each module reports its own through
`describe(api)`, so the runtime status and preflight show what this runtime actually wired. A record reads at the lowest
level among its operations, so a module whose messages mostly run reads `contract` or `inventory` when one of them is
assumed or only listed; `mirage preflight --json` (`modules`) lists every record with its operations. The levels below
are those of a Power Pages runtime with the default providers and no pack overrides.

## Scope boundary

Mirage runs one loopback organization per runtime. An area is **ours** when its behaviour or contract lives in this
repository, **external but reachable** when Mirage declares, probes and talks to a process you run, and **out of scope**
when Mirage only lists it, answers a documented placeholder, or leaves it to the platform.

### External but reachable

Mirage never starts these processes. Outbound HTTP goes through `loopbackFetch` (`dataverse-webhooks.mjs`: loopback
hosts only, a name must resolve only to loopback addresses, no redirects) and the AMQP client connects only to loopback,
so a cloud host is refused rather than reached.

| Area                            | Module (`mirage/lib/`)                                 | Level                                                   | How                                                                                                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------ | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Azure Functions, API Management | `connector-runtime.mjs` (`http`), `local-services.mjs` | contract (`local-service:<id>`)                         | A connection's `settings.rewrites` maps the cloud URL to a loopback service that `localServices` declares and probes ([local services](operations.md#local-services)); pack `httpFixtures` answer without a process. |
| Azurite                         | `storage-azurite.mjs`                                  | behaviour (contract without a usable connection string) | Core Blob REST client with Shared Key ([Azurite](storage-providers.md#azurite)).                                                                                                                                     |
| Service Bus emulator            | `message-bus.mjs`, `amqp-client.mjs`                   | behaviour                                               | Core AMQP 1.0 client over loopback TCP ([Service Bus emulator](messaging-and-outbox.md#service-bus-emulator)); a real-emulator run is a manual check.                                                                |
| Key Vault                       | `secret-resolver.mjs`                                  | behaviour for reference resolution                      | A Secret variable's reference resolves through the project `secrets` map to an environment variable or a Windows DPAPI value; no vault is contacted.                                                                 |

## Extend the stack

- **A provider.** Implement the [storage contract](storage-providers.md#contract) or a message bus and export it from a
  pack (`storageProviders`, `messageProviders`, `outboxHandlers`, `connectors`); select it with a `pack:` kind. Its
  descriptor states its level, so the registry and preflight list it. Run `runStorageContract` from
  `paqvilo/mirage/testing` against a storage provider.
- **A contract module.** Add a flat `mirage/lib/dataverse-<area>.mjs` with an `EXTENSIONS` entry
  `{ name, install(api), reset?(api), close?(api), describe(api) }`, place it in `dataverse-extensions.mjs` and import
  it from `provider-modules.mjs`. State the honest level in `describe(api)` (`behaviour` only for what this runtime
  executes, the rest as operations at `contract`); mark unconfirmed native behaviour with an `// unverified:` comment;
  answer a placeholder with a documented `501` or diagnostic, never success. Read pack overrides with
  `packOverrides(api, name)` and report repeated diagnostics once with `onceReporter` (`dataverse-addon-common.mjs`).
  Keep a setting's validation in its own `<area>-settings.mjs` that imports no runtime and add its parser to
  `settings-contracts.mjs`, so catalogue-only commands validate it without loading the runtime.
- **A pack export.** Call `registerPackExport(name, { check, key?, entries?, collide? })` in the owning module; until it
  loads, the export is only shape-checked and reported as `PACK_EXPORT_PENDING`. Add new public exports to
  `test/fixtures/public-api.json`.

Tests use the Node test runner in `mirage/test/<area>.test.mjs` with invented schemas, `x_` prefixes, port 0, temporary
directories and loopback fixtures; contract modules share `mirage/test/contract-module-fixture.mjs`. The write-volume
gate is described in [runtime performance](runtime-performance.md#write-volume-gate).
