# Liquid rendering

Mirage implements Power Pages/DotLiquid-shaped parsing and rendering: platform tags and filters, portal objects, snippets/settings, page/template relationships, FetchXML result drops, permissions, errors and whitespace behavior. Shopify Liquid is not the parity target. Source inventories identify constructs and diagnostics expose unsupported or uncertain behavior.

Use `paqvilo mirage liquid-inventory --portal <export> --json` to inventory constructs and `render-sweep --site <site> --persona all --out .paqvilo/sweep` to exercise local pages. The inventory is static coverage; the sweep is local rendering coverage. Neither establishes live parity. Record reference comparisons with a project-owned golden suite.

`paqvilo mirage inspect --source <export> --json` (or `--project`) also reports `liquidSyntax`: syntax diagnostics for imported active templates, page HTML/JavaScript/CSS, snippets, basic form/list JavaScript and advanced form step JavaScript, including imported language variants. `templateCount` and `parsePassed` describe templates; `sourceCount` and `sourceParsePassed` describe nonempty source fields. This check does not execute scripts or prove include resolution, data coverage or browser behavior. Use `liquid-inventory --include-inactive --sources` to review inactive and nonselected export sources as well.

Filters and native adapters derive from reusable platform contracts. Deployment-specific observations belong to the project's evidence and `observed` settings. A local fallback for an unsupported service is a diagnostic, not proof the service behaves identically online. See [conformance](liquid-conformance.md) and [parity evidence](parity-evidence.md).

`observed.liquidDecimalStringMultiply: "convert"` selects an evidenced site's conversion of string inputs before multiplication by a decimal operand, including string-valued site settings. Supply the capture path in `observed.evidence`. The default (or explicit `"dotliquid"`) retains the pinned DotLiquid behavior; a successful comparison on one site does not select this mode for other exports.

`observed.liquidTimesDispatch: "observed"` selects captured `times` dispatch errors for a numeric input with a string operand and string-array inputs with integer or decimal operands. Other input shapes keep their existing contracts. This also requires site evidence; the default is `"dotliquid"`.

`strip_html` preserves the DotLiquid text-transform contract and is not an HTML sanitizer. Use `escape` when displaying literal untrusted text, or `html_safe_escape` to retain safe formatting in untrusted HTML. The latter uses a parser with an explicit tag, attribute, style and URI-scheme allowlist; it removes executable markup and unsafe styles and may normalize malformed markup or void-tag spacing.

Liquid `page.id` uses an exported language-content identity when available; host navigation retains the root page identity. Exact comparisons must use equivalent authentication contexts. A synthetic signed-in persona establishes the local authentication class, but does not establish equality of contact IDs or business data.

Web link sets retain their exported title, copy and logical attributes when accessed by name or ID. Standard exports can supply copy in a separate source file; localized titles select the import LCID while raw attributes remain available. A web link's `is_sitemap_ancestor` follows the linked page's place in the current page's ancestor chain, so sibling routes with a shared URL prefix are not ancestors. These source-derived contracts follow Microsoft's [web link configuration](https://learn.microsoft.com/en-us/power-pages/configure/manage-web-links) and [Liquid object reference](https://learn.microsoft.com/en-us/power-pages/configure/liquid/liquid-objects); local regressions do not establish native response parity.

The observed parameter-entry restrictions apply only to iteration over `request.params` and its `params` alias. Source-qualified ordinary comparisons found no synthetic key/value matches through entry indexes `0`/`1`, `Key`/`Value`, lowercase variants, `Name`/`name` or bare-entry equality; direct parameter lookup continued to work. Mirage retains direct hash lookup, aliases and the actual supplied collection count. Generic dictionary pairs retain their existing numeric and named access, and ordinary loop assignment remains unchanged. These finite observations do not establish the native iterator's concrete type, its string representation, the complete hosted parameter collection or universal dictionary parity. Keep the site's sources, captures and context qualifications with its `observed.evidence`.

Keep original response bodies and source hashes in the project. A parser error without child markers requires witnessed creation, source readback and both current parent records before it can count as observed. A generic HTTP 500 before the template markers remains unqualified; changing the site's custom-error setting does not establish its cause. Source inventory, exact response comparison, service availability and successful data workflows are separate coverage claims.

`observed.pageErrorPresentation: "generic-error"` selects an evidenced GET page-query rejection structure: the generic title and heading, a fresh local Error ID in square brackets, and the fixed visible rejection message. The default `"diagnostic"` keeps simulator diagnostics. Only HTTP 500 with `PAGE_QUERY_REQUEST_VALIDATION` selects this structure; unrelated errors, other methods and API responses retain their handling. The structure does not reproduce native CSS, scripts, opaque identifiers or complete HTML bytes. Custom `Portal Generic Error` snippets and their localized Text/HTML type selection remain unqualified here. Microsoft's [error-log documentation](https://learn.microsoft.com/en-us/power-pages/admin/view-portal-error-log) specifies that Liquid inside that error snippet is not evaluated; ordinary content-snippet rendering must not be substituted for that contract.
